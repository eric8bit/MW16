# Stage 1：先确认"能不能跑起来"

这个包**只做一件事**：在桌面上画一个蓝色的 "S1" 圆点，点它会在日志里写一行。

它**不 hook 任何系统私有接口**，不改任何设置。就算失败了，最多是不出现按钮，不会有任何副作用。

## 为什么要先做这一步

因为做分屏插件需要三个前提，只要有任何一个不成立，后面全部白做：

| 前提 | Stage1 怎么验证 |
|---|---|
| 能在你的环境下编译出 roothide 格式的包 | GitHub 编译成功 = 成立 |
| dylib 能注入进 SpringBoard | 桌面出现 S1 按钮 = 成立 |
| 能在桌面上叠加自己的界面 | 按钮能点、能写日志 = 成立 |

**Step 1 通过了，后面的开发才有意义。**

## 怎么用

1. 把整个 `MW16` 文件夹传到 GitHub（见 `guides/02-云端编译自己的插件.md`）
2. Actions → 等绿色对勾 → 下载 `MW16-debs`
3. 解压，找到 `com.mw16.stage1_*.deb`，装到手机
4. **注销（Respring）**
5. 看桌面右上角有没有蓝色 **S1** 圆点

## 三种结果，分别意味着什么

### 结果 A：出现蓝色 S1 按钮，点了有反应

✅ 三个前提全部成立。告诉我，我们进入 Stage 2（真正的小窗）。

### 结果 B：没有按钮，但也没出别的毛病

说明包装上了但没注入，或者按钮没挂上。

请用 Filza 打开这个文件发我：

```
/var/mobile/Library/Preferences/mw16_stage1.log
```

如果这个文件不存在，再看：

```
/tmp/mw16_stage1.log
```

两个都没有 = dylib 完全没有加载。这时需要检查 RootHide 的注入白名单。

### 结果 C：手机白苹果 / 不停安全模式

立刻进 Sileo 卸载 `MW16 Stage1 Hello`，然后 respring。

然后告诉我。Stage1 理论上不可能导致这个（它没有任何 hook 之外的改动），
但真发生了说明环境有别的冲突，需要换思路。

## 顺便：探针也在同一个包里

如果你也装了 `com.mw16.probe`，它会写：

```
/var/mobile/Library/Preferences/mw16_probe.log
```

那个文件里有我需要的关键信息（场景接口叫什么、断言能不能用）。
**两个日志一起发我最好。**
